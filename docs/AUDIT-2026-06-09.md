## 4. `api/` と `sensors/` ルート — バックエンドと役割

**全体構成**: TV(Android端末) / BLE Recorder / SwitchBot Cloud → **LP の API ルート** → **Turso（ホスト型 SQLite / libSQL）**。メール送信のみ **Resend**。**Firebase は実コードに一切存在しない**（§6 参照）。共通バックエンドは `lib/sensor-db.ts`（`@libsql/client`）。

| ルート | メソッド | 役割 | バックエンド | 必要env | 認証 |
|---|---|---|---|---|---|
| `app/api/switchbot-webhook/route.ts` | POST | SwitchBot/BLE の人感検知イベントを `motion_events` に INSERT。失敗時 `webhook_failures` に記録。教室コンテキスト（tv_device_id/school/grade/dept/class）も保存 | Turso | `SWITCHBOT_WEBHOOK_SECRET`, `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` | `?key=` or `x-webhook-key` ヘッダ |
| `app/api/sensor-stats/route.ts` | GET | 検知統計（総件数・時間帯別・教室別）をJSONで返す | Turso | 同上 | `?key=` or `x-webhook-key` |
| **`app/api/tv/config/route.ts`** | **GET/POST** | **TVデバイス設定の配信・登録（ポーリング先）**。GET(device_id指定)=該当TVの設定+commands返却 & `last_seen_ms`/`last_known_ip` 更新（`touchTvDevice`）。GET(未指定)=全TV一覧。POST=設定 upsert（version++） | Turso | 同上 | `?key=` or `x-webhook-key` |
| `app/sensors/page.tsx` | GET(page) | 運用ダッシュボード（30秒 meta-refresh）。TV別の検知数・最終ポーリング・最新20イベントを表示 | Turso（直接 `createClient`） | `SWITCHBOT_WEBHOOK_SECRET`, `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` | `?key=`（一致しないと認証画面） |
| `app/api/application/route.ts` | POST | 広告掲載申込フォーム送信（→ メール） | Resend | `RESEND_API_KEY`（+任意 `RESEND_FROM`/`RESEND_TO`） | ハニーポット `_honey` のみ |
| `app/api/contact/route.ts` | POST | お問い合わせフォーム送信（→ メール） | Resend | 同上 | ハニーポット `_honey` のみ |

### 4-1. TV ポーリング・エンドポイントの確証
- **これが「岐南工業 TV が LP エンドポイントをポーリングしている」実体**。TV は起動時に UUIDv4 を生成し、`GET /api/tv/config?device_id=<uuid>&key=<secret>` を周期ポーリング（コメント・スクリプト記載で最大60秒間隔）。`version` 増分で設定変更を検知、`commands.wake` 等で一過性コマンドを1回だけ実行。
- DBスキーマ: `migrations/003_multi_device.sql` の `tv_devices` テーブル（`migrations/001_init.sql` で `motion_events`/`webhook_failures`、`002_tv_config.sql` → 003で `tv_config` を DROP し `tv_devices` に移行）。
- 管理スクリプト: `scripts/wake-tv.mjs`（wake送信）、`scripts/set-tv-schedule.mjs`（点灯/消灯スケジュール）。既定 `BASE_URL=https://www.school-signage.net`。
- **Turso DB**: `kimiterrace-sensor`（aws-ap-northeast-1）。SwitchBot は人感センサ(PIR)+Hub2、Cloud Webhook 経由 + ローカル BLE Recorder（Python）の二経路。

### 4-2. 留意点（セキュリティ・設計）
- `/api/tv/config` POST は同一 `SWITCHBOT_WEBHOOK_SECRET` で**書き込み・TV制御まで**可能（§3-1 の影響）。読み取り/書き込みのキー分離・POST レート制限は将来検討余地（PoC優先の設計と明記あり）。

- `switchbot-webhook` は重複イベントのデダップ未実装（`docs/POC_OPERATIONS.md:180` に既知事項として明記）。
